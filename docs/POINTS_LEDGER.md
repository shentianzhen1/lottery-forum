# 通用积分账本 V0.1

状态：设计已落地为领域规则和测试。用户接口仍返回 501，因为鉴权尚未实现。这不是现金，也不能在用户之间转账。

## 定义

积分是平台内部记账单位，只用于记录玩法结算、系统发放和受控纠错。它不是货币，不能充值、提现、兑付，也不能由用户转给其他用户。

## 记账规则

- 只使用整数。数量必须大于 0。
- 余额是账本投影，等于入账合计减出账合计。禁止直接改余额。
- 每笔记账追加一条记录，不删除、不修改历史记录。
- 余额不得成为负数。余额不足时拒绝出账。
- 每笔请求必须带幂等键。相同账户和幂等键重复提交时返回原记录，不重复记账。
- 相同幂等键但金额、方向或原因不同，拒绝并保持原记录。
- 纠错只能新增一条反向记录，并引用原记录。不能抹掉原记录。
- 操作者标识必填，供审计使用。当前还没有登录用户，所以用户接口暂不开放。

## 允许的原因

- `opening_grant`：开户发放，只允许入账。
- `game_settlement`：玩法结算。玩法插件尚未接入，规则层只保留原因。
- `correction`：受控纠错，必须引用原记录。

不设 `recharge`、`withdraw`、`transfer` 原因。

## 字段

账户：`account_id`、余额投影、创建时间。

分录：`entry_id`、`account_id`、方向、数量、原因、关联类型、关联标识、幂等键、操作者、备注、创建时间、被纠错的原分录。

PostgreSQL 迁移在 `apps/api/migrations/001_points_ledger.sql`。测试使用同等规则的 SQLite 仓库，尚未用 Docker 跑过 PostgreSQL。
