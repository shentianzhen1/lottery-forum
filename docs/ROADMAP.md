## 近期实现顺序

1. **玩法 → 彩种强绑定**
   - 在投注命令边界校验 `play_id` 所属彩种必须与 `round.lottery_id` 一致。
   - 阻断跨彩种投注/串期，补单测与 API 契约。
   - 这是开奖数据接入前的第一优先级。

2. **Android 真机主链路验收**
   - 使用 main 或待验 UI 分支的 CI debug APK。
   - 验证横屏、API 连通、注册/登录、选号、下注、取消、积分、版主页面和 960 逻辑像素门槛。
   - 真机问题按证据修，不因模拟器/截图正常直接判定通过。

3. **开奖数据采集层（先只采集）**
   - 以 PR #72 的来源调研为输入，先落 provider 接口、原始响应、来源、原始/规范期号、抓取时间和内容哈希。
   - 做号码校验、去重、更正版本、异常隔离；采集失败不推进期号。
   - 不直接接自动判奖/派奖。

4. **开奖人工确认与对账**
   - 至少连续多期与官方公告逐条核对。
   - 管理员确认后才允许进入独立判奖阶段。
   - 来源冲突、未知字段或更正必须可审计，不静默覆盖。

5. **正式化基础设施**
   - 登录失败冷却/限流、客户端网络超时/重试体验、schema migration/version。
   - PostgreSQL 在有实际数据库服务和迁移窗口后再迁移；近期不为“技术完整”提前引入 Redis。
